# 1.3.0 engineering notes

Detailed implementation history for the 1.3.0 release. `CHANGELOG.md` states
what changed for users; this document keeps the underlying investigation,
root cause, and regression detail for maintainers and future debugging.

## Added

- `blind-relabel.mjs translate` and the `findings.json` schema (documented in
  `review-protocol.md`), produced from the auditor's canonical findings after
  translating its `X`/`Y` labels back to real claim IDs.
  `independently_discovered` is derived mechanically from claim provenance,
  never taken from the auditor's own assertion. `translate` also verifies
  complete Phase 1 coverage with `--phase1-dir`: a real claim from either seat
  that appears as the origin of no finding at all is refused, the reverse of
  the hallucinated-claim-ID check.
- Canonical findings: the Phase 3 auditor groups claims describing the same
  underlying defect discovered independently by both reviewers into one
  finding, preserving which claims corroborated each other rather than
  reporting them as separate rows.
- `references/review-profiles.md`: Code, Architecture, and Document lenses,
  each a secondary rubric on the shared protocol, selectable per target
  instead of one fixed rubric.
- Optional Falsification pass: a single fresh verifier subagent independently
  checks one HIGH/CRITICAL disputed claim, with no path back to the original
  seats to re-argue it. Requested with the phrase "deep verify disputed
  high-severity findings." `translate` gained `--verification-dir` and a
  `verifications` field on `findings.json`, cross-checked against the
  verifier's own saved file in both directions (a cited file that's missing,
  and a file on disk no finding cites), and against the anonymous `X`/`Y`
  claim ID it must be named by (never a real `A`/`B` one, which would hand
  the auditor seat identity through the filename itself). The verifier
  file — not the auditor's transcription of it — is authoritative for its
  entire record (claim, verdict, basis, evidence); `translate
  --verification-dir` parses it directly and discards whatever the auditor's
  JSON supplied for `basis`/`evidence`.
- A required `auditor_check: {result, basis, evidence}` object per finding in
  `findings.json` — the structured home for the auditor's independent
  verification, which previously had no machine-readable representation.
  "Evidence outranks agreement" is now a schema-level invariant: `translate`
  refuses a `settled-refuted` finding with no actual refutation provenance (a
  peer's `disputed-with-counter-fact`, `auditor_check.result: REFUTED`, or a
  `verifications[]` entry of `REFUTED`), and refuses `settled-agree` with no
  actual agreement provenance (`independently_discovered`, a `conceded` peer
  response, or a `verifications[]` entry of `CONFIRMED`). Both review skills'
  auditor instructions now require emitting `auditor_check`.
- `scripts/release-check.mjs`: one command that runs repository parity
  validation, both packages' own validators and test suites, and Shared
  Brain's profile validation, stopping at the first failure. Package suites
  passing independently is not sufficient on its own — the repository parity
  check has caught real cross-package drift that individually-green package
  tests could not. `--release` refuses before running anything if the working
  tree is dirty, so a tag can't be certified from a state that isn't
  reproducible from `HEAD` (plain `release-check.mjs`, no flag, is unchanged).

## Parser bypasses found and fixed

Two are identity-blinding bypasses (a reviewer's real identity or a real
claim ID hidden from the blind); two are claim-fabrication bugs (a string
that isn't really a Phase 1 claim or verifier record fooling the parser into
treating it as one). CHANGELOG's "two independent identity-blinding
bypasses" bullet refers to the first two only.

- **Unbounded fence-indentation whitespace (identity-blinding bypass).**
  Fence opener/closer regexes
  accepted unbounded leading whitespace, so a fence indented 4+ spaces or
  opened with a tab (CommonMark indented code, not a fence) was still treated
  as a real fence. Content inside it — a claim ID, or identity prose like
  "The Codex reviewer found this" — was hidden from both `relabel` and `scan`.
  Both regexes now cap leading whitespace at CommonMark's 0-3 space limit —
  the safe direction for a blind, since over-scanning costs one redaction
  round while over-exempting leaks identity silently. Fence parsing was
  widened to full CommonMark rules along the way: `~~~` tilde fences,
  closing-delimiter length/character matching, and arbitrary-backtick-run
  inline code spans. Release-blocking; fixed before any 1.3.0 candidate.
- **Escaped-backtick bypass (identity-blinding bypass).** Inline code-span
  matching had no awareness of
  a Markdown backslash escape, so `` \`Codex\` `` (escaped, literal
  punctuation, never a real code span) was hidden from `scan`, and
  `` \`A1\` `` was left untranslated by `relabel`. Escape-awareness now
  applies to a span's opening delimiter only, never its closer, matching
  CommonMark 6.1 (a real span still closes correctly, e.g.
  `` `x\` Codex `y` ``). Found independently of the fence-indentation bypass
  above.
- **No fence-awareness in claim-heading extraction (claim-fabrication bug).**
  `extractClaimHeadings`
  had no fence-awareness at all: a `## A99` written inside a fenced Evidence
  excerpt (not actual prose) could fabricate a Phase 1 claim that never
  really existed. Fence-skipping was added, and the same fenced-block parser
  now makes `translate` refuse an unterminated fenced code block instead of
  silently parsing past it.
- **Code-span-stripped reconstruction bypass (claim-fabrication bug).**
  `translate`'s Phase 1
  claim-heading extraction and the Falsification pass's verifier-file schema
  parsing both tested a code-span-stripped reconstruction of each
  (already fence-skipped) line, rather than the raw line itself — a
  heading- or schema-shaped string only reachable by first removing a
  preceding inline-code span (e.g. `` `x`## A99 ``) could still fabricate a
  Phase 1 claim or satisfy the verifier schema. Both now test the raw,
  fence-skipped line for structural syntax. The same fix applied to
  `relabelText`/`countRelabelTargets`'s seat-header and rebuttal-heading
  matching, found via the mandatory post-fix class sweep.

## Worktree isolation fixes

- `--isolate` deleting an unrelated pre-existing directory, or a different
  repository's worktree, at the target path when no snapshot marker was
  present. It now refuses, distinguishing a legitimate orphaned worktree from
  another repo's via its gitdir pointer. Also refuses on a `--cd` pointing at
  a repository subdirectory instead of its root, and on a target containing a
  git submodule (previously isolated with an empty submodule directory).
- `--isolate` only fingerprinting the source repository on worktree reuse,
  never the isolated worktree's own content — since OpenCode seats have no
  CLI-enforced read-only sandbox, a worktree mutated directly (not through the
  source repo) was silently reused as if untouched. Both the source and the
  worktree's own fingerprint must now match on reuse; a worktree-content
  mismatch refuses with its own message, and a marker from before this change
  fails closed the same way any other malformed marker does.

## translate provenance/contradiction fixes

- `translate` accepting `settled-refuted` alongside an `auditor_check.result`
  of `CONFIRMED` when a peer's `disputed-with-counter-fact` alone satisfied
  the refutation-provenance check — the artifact could simultaneously assert
  "the auditor independently confirmed this" and "settled as refuted." Now
  refused, symmetric with the existing `settled-agree`+`REFUTED` refusal.
- `translate` accepting `dropped-speculative` for a finding that was neither
  speculative nor uncorroborated nor unattacked, and later for a finding a
  falsification verifier had already checked (any verdict, including
  `INCONCLUSIVE`) — a claim a verifier already checked is no longer merely an
  untouched speculative item.
- Phase 3's coin-flip relabeling: the example commands hardcoded
  `X-findings.md`/`Y-findings.md` as output filenames while only the
  `--from`/`--to` letters were told to swap with the flip result, so on half
  of all coin flips the output filename and its content disagreed on which
  label was which.
- A verifier file's `Evidence:` body is now preserved verbatim (interior
  indentation and blank lines byte-identical, CRLF and LF alike); previously
  `.trim()` on the whole joined block silently stripped real leading
  indentation and trailing whitespace, which matters for evidence containing
  code, logs, or whitespace-sensitive examples (YAML, Python). A CRLF edge
  case (a trailing `\r` on the last content line not recognized as a
  "structural blank") was caught by this fix's own regression test and
  closed with a trailing-line-terminator-only strip.
- `auditor_check.basis` is now enum-checked against the same
  `EXECUTED`/`STATIC_TRACE`/`SOURCE_CITATION`/`INFERENCE` set every other
  basis field uses, instead of only a non-empty string.

## Identity-scan hardening

- `scan` now hard-stops on any non-target-derived vendor/model token or
  seat-letter mention, not only first-person self-identification —
  third-person identity prose ("the Codex reviewer found this") previously
  passed silently. Added a content-based (not filename-based) exemption for
  seat-letter mentions when the reviewed target's own docs use seat
  vocabulary, i.e. the target is itself a review protocol like this one.
  **Behavior note:** `scan`'s exit code and stdout summary line changed — a
  run that previously exited 0 on a third-person identity mention now exits
  1; anything gating on the old summary string should re-check `scan`'s
  current USAGE text.
- Widened the seat-letter self-identification vocabulary (missing forms like
  `Seat-A`, `reviewer A`, `A-side reviewer`) and made the check
  sentence-scoped instead of a fixed 40-character window; later made
  case-insensitive on the letter (`seat a`, `reviewer a` now also hard-stop),
  since a missed lowercase mention would otherwise silently defeat the blind.
  The separate vocabulary used to detect whether a reviewed *target*'s own
  docs legitimately use seat terminology stays uppercase-only and unwidened,
  so this same false-positive shape in a target's own docs cannot
  accidentally unlock the exemption.
- `scan --tokens` added so the identity scan checks the run's actual
  configured model/provider strings, not only the hardcoded vendor list; a
  `--tokens` string is now also eligible for the target-derived exemption
  when the target's own files/docs actually name it.

## Other fixes and changes

- `relabel` now rejects `--from`/`--to` being identical, instead of reporting
  false success on an unchanged file.
- An OpenCode seat's declared `provider` must now match what its `model` ID
  actually routes to (e.g. `provider: google` with `model: anthropic/...`
  previously defeated cross-vendor validation silently). **Compatibility
  note:** a previously-valid saved config with a bare (unprefixed) OpenCode
  model ID under runtime `opencode` will now fail validation and needs
  `setup` re-run.
- Replaced the optional fourth phase (re-engaging both original reviewer
  seats for another full round) with the opt-in Falsification pass.
  **Behavior note:** a review that previously escalated a high-stakes dispute
  to a second full round now instead reports it `unresolved-high-stakes`
  unless falsification is explicitly requested; the `escalate-extra-round`
  final state and `phase4/` result directory no longer exist.
- `translate`'s verdict/`final_state` contradiction checks are no longer
  scoped to single-origin findings: any `CONFIRMED` `verifications[]` verdict
  anywhere in a finding now forbids `settled-refuted`, and any `REFUTED`
  verdict forbids `settled-agree`, regardless of how many origins the finding
  has — a canonical finding groups claims only when they assert the SAME
  underlying defect, so one origin's verdict speaks for the finding as a
  whole.
- `translate` refuses `settled-agree` when any `peer_responses` entry is
  `disputed-with-counter-fact`, unless a `verifications[]` entry for that
  finding is `CONFIRMED` (the Falsification pass's own designated mechanism
  for settling a disputed claim). **Behavior note:** a single-origin
  `EXECUTED`+`REPRODUCED` claim the peer disputes without a counter-fact,
  with no independent discovery and no falsification verifier, is now
  `unresolved-*`, not `settled-agree` — bare disagreement no longer needs a
  counter-fact to prevent settlement; it now also needs the auditor or a
  verifier to affirmatively settle it.
- Fixed the win32 shell-injection guard (`assertWin32Safe`) being untestable
  on non-Windows CI, since it read the real process platform directly instead
  of the injectable parameter its caller accepted.
- Fixed a documentation contradiction on which seat's findings file receives
  a peer's rebuttal; corrected to match the actual, tested behavior.

## Documentation and metadata

- `review-protocol.md`'s Blind exchange and Falsification pass sections, and
  `pair-review`'s Review workflow step 7, reformatted from long dash-chained
  sentences into atomic MUST/MUST NOT/numbered-step prose; no rule semantics
  changed, verified by side-by-side read-through of each rewritten section
  against its prior wording (the code and both test suites are untouched by
  this pass and prove nothing about prose-only intent).
- `phase-3-scorecard.md` received the same treatment in a later pass: its
  dense Falsification pass and translate-refusal-condition paragraphs were
  broken into MUST/MUST NOT lists and lettered/numbered steps. Verified
  afterward, by direct diff, that the same set of rules (the
  `settled-refuted`/`settled-agree` contradiction checks, the
  `disputed-with-counter-fact`-unless-CONFIRMED-verifier rule, and the
  `dropped-speculative` conditions) still appear in substance in both this
  file and `review-protocol.md`'s own restructured wording of the same
  rules; the two files are not required to be byte-identical (only
  `blind-relabel.mjs`, its test file, and `review-protocol.md` itself are
  synced between packages) but should not silently diverge in meaning.
- Removed `marketplace.json`'s "Production-ready" framing and the `reviews`
  plugin's stale `confidence-floored`/code-only description; both now
  describe the actual, current evidence-graded, multi-target scope.
- `SECURITY.md` now names every provider a `cross-review` seat can actually
  reach (an OpenCode-routed seat can send reviewed material to Google or
  another configured provider, not only Anthropic/OpenAI), states
  `pair-review`'s narrower Anthropic-only scope, and documents that both
  skills can execute commands from the reviewed repository as a separate
  trust boundary from sending text to a model provider.
- Reworded the plugin description and `review-profiles.md`'s
  profile-selection guidance to drop stale "confidence"/"code review" framing
  that predates Basis/Evidence-strength and the Architecture/Document
  profiles.

## Test/CI investigation

`release-check.mjs`'s test-suite steps run with `--test-concurrency=1` after
`validate-package.test.mjs`'s spawned child was observed to crash
intermittently under the full parallel test-file glob during earlier
development (3/3 clean both serial and isolated at the time). The exact
contention was never isolated at the time, and no failure signature was
persisted.

A later stress-test pass (22 runs total: 6 from an earlier verification
pass, plus 8 fresh runs of each package in default parallel `node --test`,
no concurrency flag) reproduced zero failures. CI already runs default
parallel `node --test` and has shown no corresponding failures. This
contradicts the original localization to `validate-package.test.mjs` and
means release-check's blanket serialization is currently a precaution
against a bug that cannot be reproduced, not a fix for a confirmed one.
Tracked as a 1.4.0 item: replace the blanket serialization with a single
shared test-runner script both CI and release-check call, so both gates test
the same execution mode, and stop claiming a root cause that was never
confirmed.

## Known limitations at 1.3.0

- `relabel`/`scan`'s inline code-span matching is single-line only, unlike
  CommonMark's real grammar, which permits a span to cross a line ending. A
  genuine multiline code span's claim IDs get relabeled and identity tokens
  get scanned instead of staying exempt — fail-safe (over-scanning), never a
  leak, but it can mutate evidence/source snippets that legitimately span
  lines. Deliberately not fixed with a naive "span stays open until the next
  matching backtick run" parser, which would itself create a blinding bypass
  by letting one unrelated stray backtick swallow real headings and claim IDs
  in between.
- `scan`'s target-derived exemption is token-global: it does not distinguish
  "this specific occurrence cites the target" from "this token merely occurs
  somewhere in the target."
- A canonical finding's own `evidence`, `severity`, `basis`, and
  `evidence_strength` are still transcribed from the auditor's JSON and
  trusted as-is; `translate` enforces their shape but does not yet
  cross-check them against the finding's actual Phase 1 origin content the
  way `verifications[].basis`/`.evidence` are cross-checked against a
  verifier file.
- The Falsification pass's `disputed-with-counter-fact` peer-response
  classification is still the auditor's own reading of Phase 2; `translate`
  does not yet mechanically parse Phase 2 rebuttal artifacts to confirm a
  `Counter-fact:` line actually existed and was non-empty.
- The fresh Phase 3 auditor can still be the same model family as one or both
  reviewers; `manifest.json`'s `auditor_model_family` records this known
  self-preference risk for the orchestrator's own review, but the protocol
  does not yet require or default to a third, independent provider for the
  auditor role.
- gitignored files and untracked nested git repositories are excluded from
  `--isolate`'s drift/change detection, including its own self-fingerprint on
  worktree reuse; the snapshot fingerprint is taken before the worktree copy
  runs, so a write to the target in between is not detected.
- `cross-review`'s two provider dispatchers (`codex-dispatch.mjs`,
  `opencode-dispatch.mjs`) both pass the full, unfiltered parent environment
  to spawned provider CLIs. `pair-review` has no dispatcher — its seats are
  harness subagents — and is unaffected. No `execution_policy`
  (never/ask/allow) concept exists anywhere.
  External provider processes have no default timeout — `--timeout` exists
  but defaults to `null` (unbounded) unless explicitly passed. Tracked for
  1.4.0.
