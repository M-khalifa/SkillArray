# 1.3.0 engineering notes

CHANGELOG.md says what changed. This is the detail behind it, for anyone
debugging the same class of bug later.

## findings.json and canonical findings

`blind-relabel.mjs translate` produces `findings.json` from the auditor's
canonical findings, translating `X`/`Y` labels back to real claim IDs.
`independently_discovered` is derived from claim provenance, not taken
from the auditor's say-so. `translate --phase1-dir` also checks that
every real Phase 1 claim shows up as the origin of some finding — the
mirror image of the hallucinated-claim-ID check.

Canonical findings group claims that describe the same underlying defect
when both reviewers found it independently, into one row instead of two,
and record which claims corroborated each other.

`findings.json` now requires an `auditor_check: {result, basis,
evidence}` object per finding, and enforces "evidence outranks agreement"
at the schema level: a finding can't be marked `settled-refuted` without
actual refutation evidence, or `settled-agree` without actual agreement
evidence. Bare auditor say-so no longer settles anything.

The optional Falsification pass sends one disputed HIGH/CRITICAL claim to
a fresh verifier with no path back to the original seats. Requested with
"deep verify disputed high-severity findings." The verifier's own file,
not the auditor's summary of it, is authoritative for that claim's
verdict, basis, and evidence.

## Four parser bugs, two of them real blinding leaks

- **Fence indentation.** The fence regex allowed unlimited leading
  whitespace, so a 4+ space or tab-indented block (CommonMark treats that
  as plain indented code, not a fence) still got treated as a real fence,
  hiding whatever was inside it — including identity leaks — from both
  `relabel` and `scan`. Fixed by capping leading whitespace at
  CommonMark's actual 0-3 space limit. Release-blocking; fixed before any
  1.3.0 candidate went out.
- **Escaped backticks.** `` \`Codex\` `` is an escaped literal, not a
  real code span, but the inline-code matcher didn't know that, so it
  hid identity mentions that should have been caught. Fixed to recognize
  the escape on a span's opening delimiter (matching CommonMark), found
  independently of the fence bug above.
- **Fenced claim headings.** A `## A99` written inside a fenced Evidence
  excerpt (quoted text, not a real claim) could get parsed as if it were
  an actual Phase 1 claim. Fixed by making claim-heading extraction
  fence-aware.
- **Code-span-stripped reconstruction.** Both `translate`'s claim
  extraction and the Falsification verifier's schema check tested a
  version of each line with inline code spans already stripped out —
  which meant a string like `` `x`## A99 `` could still fabricate a
  claim once its leading code span was removed. Fixed to test the raw,
  fence-skipped line instead. The same bug existed in `relabel`'s own
  seat-header and rebuttal-heading matching; found by sweeping for the
  same shape everywhere else it could recur.

## Worktree isolation

`--isolate` used to delete an unrelated directory (or another
repository's worktree) at the target path if no snapshot marker was
present. It now checks the gitdir pointer and refuses instead. It also
used to fingerprint only the source repository on reuse, never the
worktree's own content, so a worktree mutated directly (not through the
source repo) got silently reused as if untouched. Both fingerprints have
to match now.

## Other real fixes

- `translate` used to allow contradictory states in the same finding —
  simultaneously `settled-refuted` and independently confirmed by the
  auditor. Now refused.
- Identity scanning used to catch only first-person self-identification.
  Third-person mentions ("the Codex reviewer found this") passed through
  silently. Now caught, case-insensitively, sentence-scoped instead of a
  fixed character window.
- An OpenCode seat's declared provider now has to match what its model
  ID actually routes to — previously a mismatched pair defeated
  cross-vendor validation silently.
- The old optional fourth phase (a full second round for disputed claims)
  is gone, replaced by the Falsification pass.
- A disputed claim with no counter-fact, no independent discovery, and
  no falsification check now reports as unresolved instead of settled —
  bare disagreement alone used to be enough to block settlement, but
  wasn't enough to make it either.
- Fixed a verifier file's `Evidence:` body getting `.trim()`-mangled,
  which silently stripped real indentation and trailing whitespace from
  evidence containing code or logs.
- Fixed a documentation contradiction over which seat's file receives a
  peer's rebuttal.

## The parallel-test flake that wasn't confirmed

`release-check.mjs` ran its test suites serially for a long time because
`validate-package.test.mjs` was once seen crashing intermittently under
parallel scheduling. The actual cause was never isolated. A later
22-run stress pass reproduced nothing, and CI had been running parallel
the whole time anyway with no corresponding failures. The serialization
was a precaution against a bug nobody ever actually confirmed. Dropped
in 1.4.0 — those 22 runs predate, and don't cover, a separate
`dispatch-integration.test.mjs` timeout found later under real
concurrent load.

## Known limitations at 1.3.0

- Inline code-span matching is single-line only, so a real span crossing
  a line ending doesn't stay exempt from relabeling/scanning. This
  is fail-safe, not a leak, but a naive fix here would open a real
  bypass by letting one stray backtick swallow everything after it.
- The identity scan's target-derived exemption doesn't distinguish "this
  occurrence actually cites the target" from "this token happens to
  appear somewhere in the target."
- A finding's evidence/severity/basis are still transcribed from the
  auditor's JSON and trusted as-is, not cross-checked against the
  original Phase 1 claims the way verifier records are.
- The Falsification pass's dispute classification is still the auditor's
  own reading of Phase 2, not a mechanical check of the actual rebuttal
  text.
- The Phase 3 auditor can be the same model family as a reviewer. This
  gets recorded, not prevented.
- `cross-review`'s dispatchers pass the full parent environment with no
  execution-approval concept and no default timeout. Fixed in 1.4.0.
